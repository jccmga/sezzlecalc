# Prompts

This file records the AI prompts used during this assignment, so the work is reproducible and auditable.

The table below has one row per pipeline stage that ran for the `internal/calc` domain-package feature. `Source` is taken from the raw log (`user` = a prompt the human authored; `agent` = a delegation prompt one subagent handed to another). Prompts are summarized, not dumped verbatim — the complete, unedited text lives in [`docs/ai/prompt-log.md`](docs/ai/prompt-log.md), which is the raw appendix for this table.

| Stage | Source | Prompt | Why | Outcome |
|-------|--------|--------|-----|---------|
| PRD parse | user | Take this feature through the full pipeline. Create the Go module `./backend` and an `internal/calc` package exposing stateless arithmetic for `add`/`subtract`/`multiply`/`divide` via `func Evaluate(operation string, a, b float64) (float64, error)`, with sentinel errors (e.g. `ErrDivideByZero`), no `net/http`, `go 1.22` as the explicit minimum with no `toolchain` line, and table-driven tests covering positive/negative/zero/fractional operands and divide-by-zero including a `-0.0` divisor. Out of scope: HTTP layer, extra operations, frontend. Delegate each step to its owning subagent. | The human's original feature request defines the whole acceptance surface — signature, sentinel errors, HTTP-free constraint, toolchain pinning, and the test matrix. | Delegated to `@prd-parser` → PRD written at `docs/opencode/prds/calc-domain-package.md` (six decisions left open for clarification). |
| Clarify (user decisions) | user | Resolve the PRD's open questions: module path → `sezzlecalc/backend`; keep `ErrUnknownOperation` as a sentinel; `NaN`/`±Inf` pass through with IEEE-754 semantics; operation matching is case-insensitive + whitespace-trimmed. Update the PRD in place and mark it Resolved. | Turns the PRD's open questions into final, testable decisions (Q-1, Q-3, Q-4, Q-6), removing ambiguity before planning. | PRD updated in place; status → "Resolved — all open questions decided". |
| Plan | agent | Produce a concrete, file-by-file implementation plan from the PRD at `docs/opencode/prds/calc-domain-package.md`; write it to `docs/opencode/plans/calc-domain-package.md`. | The `@planner` subagent turns the resolved PRD into an exact file inventory, exact `go.mod`/`calc.go`/test contents, rollout order, and an AC traceability table. | Plan written at `docs/opencode/plans/calc-domain-package.md`. |
| Plan review | agent | Review the plan against its source PRD and repo state for completeness, correctness, test rigor, and feasibility; report a Pass/Fail verdict. | The `@plan-reviewer` subagent stress-tests the plan (go.mod exactness, divide-by-zero guard, `-0.0` test construction, AC coverage) before any code is written. | Verdict: **Pass** with non-blocking tightening notes. |

| Verify (QA) | agent | Independently verify the implemented package: `go build`, `go test -race -count=1`, `go vet` + `gofmt -l`, coverage, `go list -deps` (no `net/http`), and `git status` — reporting raw command output, not prior claims. | The `@qa-lead` subagent re-runs the full gates itself and reports raw evidence so success is not taken on trust. | All gates pass: build, `go test -race`, vet/gofmt, coverage at 100% statement coverage, no `net/http` in `internal/calc` deps, and only the expected files in `git status`. |
